## 可执行行为（对应 execution/tests）
1. test_steps：手工草稿必含任务及步骤完成标准；1–12 个一层步骤，估时区间可空；只采纳用户选择的节点，含依赖者必须同时采纳前置节点；追加不覆盖。原父状态/每周投入保持。自依赖、循环、未知节点、跨任务关联拒绝。
2. test_rules：剩余工作 [300,540]，可用 480 分钟→有条件；小于300→冲突，大于等于540→时间符合但不保证成功；未知→信息不足；每周投入不直接当总可用时间。
3. test_ledger：逐次正整数分钟记录，40+50+90=180；父任务单独20→200；迁移归属不复制；无记录为 null，作废记录不计；修改保留前后审计。按实际投入日期记录，允许历史补记但不自动启动任务。
4. test_completion：完成标准可见；完成说明和链接可选，仅 http/https；无耗时仍可完成并显示未记录；已有90补30→120；状态、耗时、事件、回执原子提交。必要步骤完成仅提示，父任务提前完成需要确认未完成步骤。撤销恢复前状态、保留时间；父已结束时先恢复父任务。核对耗时独立操作，改账后待确认。
5. test_isolation：任务、步骤、草稿、分析、时间和事件所有读写限定当前账号；伪造 owner/关联拒绝；跨账号404，无副作用。
6. test_idempotency：相同键与相同内容重试仅一次写入；同键改内容409；不同账号命名空间独立。
7. test_conflict_and_rollback：旧版本409；账本/步骤更新推进父版本；故障无半条完成。两个并发写同版本恰一成功；并发重复请求仅一条记录。
8. test_lifecycle：父暂停继承显示；依赖未完成阻止开始；父未启动/结束不能启动步骤；前置撤销后依赖操作重新检查。
9. test_jobs：用户确认将发往 DeepSeek 的当前任务快照；队列持久化，每用户最多一个活动任务；取消不应用晚到结果；重新分析新草稿保留旧步骤；worker 重启将中断任务标为可重试，不自动再次计费。
10. test_provider：真实 HTTPS 边界契约以模拟服务响应测试；结构/范围/依赖均验证，最多一次请求，本版不自动重试收费；超时/限额/异常安全报错；不暴露密钥或返回原始错误；未配置明确提示，手工功能正常。真实付费验证需要用户本机密钥，若没有不得宣称已验证。
11. test_properties：账本汇总、未知值、规则区间和幂等性属性测试。
12. 浏览器：注册登录、手工草稿→采纳→步骤执行→记时→完成→撤销；前端失败保留草稿、刷新后持久；桌面与390px；XSS文本、用户切换无泄漏。
13. 原24项 API 测试继续通过；第二部分完成入口变化需兼容已有 API：旧 PATCH status=completed 也统一调用完成规则，不能绕过事务；第一部分原版独立通过测试。

## 失败模型与验证
重复记时→幂等和并发测试；越权→敌意请求与浏览器双账号；半条记录→事务注入故障；时间算错→属性测试与手动变异；数据库丢失→迁移备份、迁移回滚演练、重启持久性；AI注入或畸形→严格schema、外部边界契约；后台中断→重启恢复测试；UI丢草稿→真实浏览器；目录移动破坏入口→两端口冷启动与文件哈希核对。

最终 tools/verify.sh 运行全测试、静态类型、格式、覆盖率、变异、迁移与浏览器；证据中如实记录覆盖缺口和外部 API 尚未实测等限制，任何失败修复后重跑。不把模拟模型输出冒充真实调用。
