# 第一部分可执行验收规格

已授权范围：用户确认此前 PDF 设计并要求运行一版，重点是任务隔离。本规格由代理自主细化，未取得逐条人工复核（spec approval: not obtained (autonomous run)）。采用 Tier 3，结论限于已验证场景。

## 环境与实现计划

- 新建独立 taskflow 目录，保留已有 PDF/PNG，不修改全局 Python 环境。
- Python 虚拟环境；Django 5.2 LTS：账号哈希、数据库会话、CSRF、ORM、事务、测试框架；SQLite：本机持久存储，无额外数据库服务。
- 原生 HTML/CSS/JavaScript：同源网页，无外部 CDN、无前端构建依赖。
- 开发依赖 coverage（覆盖率）、ruff（静态检查和格式）、mypy 与 django-stubs（类型检查）、hypothesis（性质测试）、pip-audit（依赖漏洞）、playwright（浏览器验收）。解析出的传递依赖一起锁定；运行与开发依赖分开记录。
- 本地监听 127.0.0.1，提供启动脚本；不部署公网、不调用 AI 或外部业务服务。
- 尚无 Git 仓库：建议未来 git init；本轮不自动创建提交，使用可复算源码树哈希标识状态。
- 输出 tests、tools/verify.sh、SPEC.md、EVIDENCE.md、README.md、固定版本依赖、数据库迁移、浏览器截图与验收日志；运行数据与密钥忽略提交。

## 验收场景（测试名对应场景）

1. register_login_logout：合法账号注册后自动登录；重复账号和弱密码返回 400；错误登录返回 401；退出后会话不可用；密码不是明文。
2. anonymous_denied：匿名列表、详情、创建、修改、历史均返回 401，不返回任务内容。
3. isolation：甲创建任务后，乙列表无该记录；乙凭任务 UUID 读取/修改/状态历史均为 404；记录保持不变。
4. forged_owner：提交 owner/user_id 等未经支持字段返回 400；查询 owner 参数不能扩展登录用户范围；归属始终由会话确定。
5. create_persist：名称即可创建，默认 planned，周投入未知；刷新/重新登录/数据库连接重开后仍可读取；0 分钟与未知区分。
6. validation：空白名称、超长文本、负数/小数/布尔型时间、无效状态、非对象 JSON、损坏 JSON、未知字段被拒绝；错误时无数据变化。
7. status_history：planned → in_progress → paused → in_progress → completed → abandoned，沿用原 UUID；每次真实状态变化产生一条历史，同状态更新不产生重复历史。
8. optimistic_conflict：客户端提交已过期版本返回 409；较新的任务内容与历史不被覆盖；两个线程使用同版本并发更新，最多一次成功。
9. idempotency：同用户相同创建请求键与内容只创建一条；相同键不同内容返回 409；不同用户可使用同一键且数据分属各自；未知保存结果可安全重试。
10. atomic_rollback：状态变更记录写入失败时，任务状态与版本一同回滚。
11. csrf：无 CSRF 的注册/登录/创建/修改/退出返回 403；正常同源 token 可操作；会话 Cookie HttpOnly / SameSite=Lax。
12. brute_force：同来源连续登录失败触发 429，正常成功登录清理失败计数；不记录密码。
13. property_isolation：多种输入文本和投入时间往返一致；任意生成的合法任务不能被另一账号访问或修改。
14. browser_workflow：桌面注册、空清单、新建、编辑、取消、暂停、恢复、历史、搜索、刷新/重登、退出切换账号；手机布局无横向溢出。
15. browser_failure：模拟保存请求网络失败，表单保留原输入并显示未保存；任务文字按文本渲染，HTML 不执行。
16. browser_stale_session：401 清空已加载任务；内存草稿绑定原用户，切换账号后不能看到；同账号重登可恢复。
17. no_delete：不提供永久删除接口，不把放弃等同于删除；拒绝 DELETE 且记录保持。

## 失败模型与针对性约束

- 越权 / 客户端伪造归属：多用户 API 集成测试、生成性质测试、删除 owner 条件的变异测试。
- 丢失更新 / 部分写入 / 重试重复创建：CAS 版本更新、真实事务回滚测试、线程并发测试、幂等键约束与变异测试。
- CSRF / XSS / 暴力登录 / 会话过期：强制 CSRF 客户端测试、浏览器恶意文本与过期场景、限流测试。
- UI 假成功与丢草稿：浏览器中断网络并断言未保存；从服务器返回任务后更新界面。
- 持久化失效：数据库连接重开、独立服务器重启验收。
- 迁移失败：空库迁移、回退应用迁移再迁入；不在用户实际数据库上回退。
- 已知界限：本地单实例原型；没有公网部署、分布式限流、密码找回邮件、负载计算、AI、永久删除或长期草稿存储；浏览器关闭后未保存草稿丢失。

## 冻结规则

测试断言建立后不为了通过而放宽。新增行为追加说明。RED 先针对 501 占位路由运行，记录每个测试的行为失败。最终检查统一由 tools/verify.sh 执行并留存日志；被跳过的检查明确标注，不声称已验证。

## 追加：多标签页账号切换与恶意编码

- 浏览器多个标签页共享会话。前端携带当前界面账号编号作为“页面是否过期”的检查值；实际授权仍以服务端会话为准。编号与当前会话不符返回 401，不能把甲的草稿误存到乙账号；页面重新获得可见性时检查登录身份。
- JSON 中孤立 UTF-16 代理码点、NUL、超限请求体返回 400，不产生数据库 500。新增 adversarial 测试先运行 RED，再修改实现。

## 浏览器验收样本修正

首次全 DOM 隔离断言使用“修改论文实验图”，恰好与界面静态示例占位文本重名，产生误报。将验收任务统一改为带“隔离验收：”前缀的名称；仍然断言完整 DOM 中不存在甲的私有任务标题和草稿，不放宽隔离要求。

## 追加：审计发现的安装工具修复

最终审计发现虚拟环境继承的 pip 26.0.1 有已知漏洞记录。仅在项目虚拟环境升级为 pip 26.2.1，用于安全安装依赖；requirements-dev.txt 记录包括 pip 在内的完整版本，首次启动脚本也先安装此版本。没有修改全局 pip。审计使用项目内缓存，避免宿主旧缓存反序列化告警。全部检查重新执行。
