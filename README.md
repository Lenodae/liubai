# 留白

一个从任务记录、分析拆分，走到执行与实际耗时反馈的个人任务空间。

| [第二部分_分析与执行](第二部分_分析与执行/) | 第二部分完整应用、规划书、DeepSeek 配置与启动入口 | http://127.0.0.1:8001/ |

每部分的 `代码/`、`规划书/` 分开保存。第二部分复用基础功能的独立副本，新功能集中在 `execution` 模块。两版各自使用独立数据库、会话、密钥与虚拟环境。

## 在 Mac 上运行

安装 Python 3 后，双击根目录 `打开留白.command` 默认启动第二部分。也可以进入各部分目录，双击对应入口。首次启动自动创建虚拟环境、安装运行依赖并创建空数据库。

GitHub 中不包含本机用户账号、任务数据库、登录会话、密钥、虚拟环境和运行日志。首次克隆需要重新注册账号；电脑上的原始数据仍保留在各自 `代码/.local/` 目录。

第二部分的 DeepSeek 密钥通过 `配置 DeepSeek.command` 在本机填写，不要提交到仓库。手工拆分、规则分析、完成登记和耗时账本不依赖模型服务。

## 第二部分使用流程

保存目标与条件 → 手工拆分或生成草稿 → 编辑并采纳 → 步骤执行 → 记录实际耗时 → 核对完成。

- 每周计划投入、预计总耗时和实际耗时分别记录。
- 父任务汇总各子步骤的有效耗时，避免重复登记。
- 完成、撤销、补记、修改和删除保留相应历史。
- AI 结果先进入草稿，由用户采纳；不会自动改变任务状态或实际耗时。

## 规划与验证

各部分 `规划书/` 中保存架构 PDF、实施说明、SPEC 和 EVIDENCE。第二部分已完成 51 项测试及浏览器验收；真实 DeepSeek 付费调用尚需本机配置后验证。

安装 `requirements-dev.txt` 后，可在各自代码目录运行 `bash tools/verify.sh`。证据日志、截图和覆盖率文件可重新生成；本机目录迁移/数据隔离检查依赖原电脑的历史快照，新克隆不能直接复现这项历史状态检查。
