## 验收行为

1. 进行中任务 A 的步骤 1、2 完成，3 可执行，4 依赖 3：首页继续区和任务卡直接显示步骤 3、完成标准和步骤 4；4 标明完成当前步骤后可做。
2. 有明确进行中的可执行步骤时优先显示它，否则按原步骤顺序选择依赖满足的待开始步骤。暂停、放弃、已完成及依赖不满足的步骤不能作为快捷完成目标。
3. 没有步骤显示拆分入口；全部完成提示核对整个任务；只有受阻/暂停/放弃步骤时明确说明，不制造可执行步骤。
4. 勾选通过现有 complete 接口落库，成功后更新当前和下一步、进度、足迹及鼓励。只登记步骤完成，不自动登记耗时、不核对耗时完整性、不结束父任务。
5. 最近一次成功完成保留明显的撤销和查看记录入口。撤销沿用原接口，保留耗时并重新计算可执行步骤。
6. 连续点击最多发起一次写入；网络/服务异常保留原请求与幂等键，只有用户点击重试才重发。版本冲突不覆盖新数据，刷新并提示核对。
7. 账号或登录轮次变化时，清空快捷状态，旧响应不能写回当前页面。所有读取/写入仍由服务器检查所属账号。
8. 标题与完成标准只作为文本显示；不嵌套交互控件；支持键盘与 390px 手机宽度。
9. 读取摘要无写入副作用，任务列表的步骤读取使用批量预取，避免逐任务请求。

## 失败模型与验证

- 依赖选择错误：后端选择契约和真实浏览器链式步骤验证。
- 重复完成/丢失响应：原版本/幂等保护 + 浏览器延迟、丢失响应、重试。
- 账号切换泄漏：原归属 API 测试 + 浏览器迟到响应检查。
- 实际时间或父任务被改动：真实 API 写入后检查账本/父任务状态。
- 界面按钮失效、注入或溢出：浏览器实际执行、文本渲染和手机布局检查。
