# 留白 · 第三部分：负载建议与分析

双击上一级「打开留白.command」，打开 http://127.0.0.1:8002/ 。登录后先进入预算与当前任务总览。

第三部分是可独立运行的完整应用：`tasks` 保留任务基础，`execution` 保留拆分、完成与耗时记录，新增 `load_analysis` 专门处理预算、负载和期限。它拥有自己的 `.venv`、`.local/tasks.sqlite3`、会话 Cookie 和密钥。第一部分 8000、第二部分 8001 仍可独立使用。

本机已通过 SQLite 一致性备份复制第二部分的账号与任务，原账号密码可沿用；复制后的两边不会自动同步。导入前副本保存在 `.local/phase2-import-backup.sqlite3`。未复制登录会话。第三部分首次初始化未迁移 DeepSeek 配置；现已补迁移第二部分已有配置，保留原验证时间，并独立保存。刷新网页即可查看配置状态；之后可在「DeepSeek 设置」修改。负载计算无需 AI。

## 从哪里开始

1. 登录默认看「整周计划」。直接在圆环右侧按“小时＋分钟”填写或调整总预算与留白，一键保存后更新图表；手机上输入区在同一张卡片内向下排列。两格都空表示未知，填0表示已确认零时间。整周与本周剩余分别保存；原先填写的剩余预算可切换到「本周剩余时间」查看。
2. 默认入口是「添加想法」。先记录内容，尚未决定执行的想法保存为待选择（`planned`），不占用总体预算。可选「本周任务」或「长期每周任务」来记录所选周或每周的计划时间；填写时间本身不会启动执行。
3. 明确开始后变为「进行中」（`in_progress`），才按适用周的计划时间计入负载。正在进行但时间未填写时显示待确认，不能当成0；明确填0才是已确认的零投入。
4. 预算分配环读取同一份预算分析结果，按小时和分钟显示进行中任务占用、留白和可再安排时间，旁边列出对应任务的时间与修改入口。例如4680分钟显示“78小时”，90分钟显示“1小时30分钟”。添加想法不会减少可再安排时间；开始、暂停、恢复、完成或修改计划时间后，数值和圆环同步更新。总预算未知时仍展示已知投入，但不猜占比；超出净容量时显示缺口。
5. 暂停（`paused`）、完成（`completed`）或放弃（`abandoned`）不占当前预算；恢复为进行中后重新计入。本周任务仅适用于所选周；长期任务在适用周内持续执行时计入，暂停与结束后释放。完成子步骤不改变父任务状态，也不自动释放父任务占用。
6. 每周总时间属于整项任务的计划，推进、维护和子步骤不能重复相加。人工窗口计划优先替代该窗口自动值，也只对进行中的任务计入。当前先落实状态与时间联动；就绪队列、阻塞队列等完整调度机制尚未作为独立模块实现。
7. 比较方案先预览，再采纳。没有后续事实变化、也未跨日时可撤回；旧页面和并发提交会要求刷新，网络不确定时可重试同一请求。历史快照保留当时结果，规则更新不会改写已保存快照。
8. 实际投入通过原耗时账本记录，并在总览单列。计划占用与实际耗时分别记录；本周剩余窗口不直接复制整周时间，已记耗时也不会再次扣减本人已确认的剩余预算。
9. 「期限检查」核对未来四周共享容量。未拆分的每周总计划不能冒充已知目标剩余工作或维护，需明确确认期限分段与其他占用；缺失资料不按周预算除以7猜测。
10. 「每周回顾」按真实账本日期汇总投入，查看已保存计划和调整记录。历史自动计划使用当周记录；没有当时资料的窗口显示待确认。

原迁移保留了既有任务的每周计划；当前只有进行中的任务按计划计入预算，想法和暂停任务无需删除计划时间。任务搜索只筛选展示，不改变总负载。

圆盘的颜色和数值表达预算分配：例如预算600分钟、留白60，净容量540；进行中任务180分钟，尚可安排360。再添加一个计划240分钟的想法，仍可安排360；开始执行该想法后占用合计420，尚可安排120。这份分配图不表示人的健康或能力。

现在也会用文字描述安排的节奏：净容量负载低于60%为“轻松有余量”，60%至不足80%为“刚刚好”，80%至不足90%为“有点挑战”，90%至不足100%为“负载偏高”，100%为“安排已满”，超过100%为“该减一点”。负载分母是总预算扣除留白后的可安排容量；圆环仍以总预算展示分配。区间按上界提示并展示范围，未知或过期信息不生成完整百分比。

确认完成一个步骤或整个任务后，会出现一条带名称的鼓励，6秒后收起；悬停或键盘聚焦时暂停收起，也可以直接关闭。页面顶部“完成鼓励：开/关”保存本机当前账号的选择。编辑完成说明、撤销、刷新或失败的保存不会触发；成功重试按完成事件去重。步骤完成数量仅说明步骤数量，不推算耗时进度。计划PDF、源码和示意见上一级 `规划书/负载感受与进度鼓励/`。

任务卡片和详情顶部现在都提供“删除”。点击后移入回收站，立即释放当前与未来预算，可以直接“撤销删除”，也可以从导航“回收站”恢复；回到删除前的状态，进行中的任务会重新计入预算。步骤、完成记录、实际耗时与历史快照保留。回收站不自动清空；“放弃”仍是独立的任务状态。网络结果不确定时用“核实并重试”确认同一次操作，版本冲突则先重新载入，避免覆盖其他页面的修改。

总览标题下方新增“今日鼓励”：从本地300句语句中，按设备的日历日期每天展示一句，同日刷新不换，连续300天不重复，之后循环。跨午夜或重新回到页面会更新；这与任务完成时的鼓励提示相互独立。句库、来源及许可保存在 `static/data/`，运行时只读取本机文件，不调用DeepSeek或外部语句接口。文件暂时读取失败时仍显示一句温和提醒，并可重新载入。

## 独立目录

- `load_analysis/rules.py`：纯计算、区间与累计期限检查。
- `load_analysis/workspace.py`：窗口/任务/账本读取与来源指纹。
- `load_analysis/services.py`：预算与计划保存、预览、原子采纳、幂等回执、撤回、回顾。
- `load_analysis/deadlines.py`：四周容量与期限分段汇总。
- `load_analysis/models.py`、`migrations/`：独立预算、任务预留政策、任务计划、调整历史和快照。
- `load_analysis/policies.py`：周任务/长期计划、状态占用与每周变更记录。
- `static/budget_reservation.js`、`budget_reservation.css`：预算分配环与添加后反馈。
- `static/load_feeling.js`、`load_feeling.css`：统一的负载分级、文字与颜色。
- `static/encouragement.js`、`encouragement.css`：完成事件鼓励、去重、关闭与账号本机偏好。
- `static/daily_encouragement.js`、`daily_encouragement.css`、`static/data/daily_encouragement.json`：总览每日鼓励、300句本地语句及日期轮换。
- `tasks/lifecycle.py`、`static/task_trash.js`、`task_trash.css`：任务删除、回收站恢复、撤销与失败重试。
- `static/load.js`、`load.css`：预算总览、建议、期限与回顾界面。
- `../规划书/`：既有 PDF、生成源文件、本次 SPEC 与 EVIDENCE。

本版已加入预算分配圆环与添加反馈；历史自动校准、高注意力维度和 AI 解释仍为后续迭代。原圆盘专项计划保留。上一级 `规划书/预算自动预留与添加反馈/` 中的9页演示 v1.0 记录了上一轮「创建即预留、暂停保留」的旧方案，已由1页 `进行中任务预算_规则修正_v1.1.pdf` 修正；请以 v1.1 和本说明为准。PDF 及可复现源文件均保留在该专项目录。

## 运行与验证

Python 3.14；依赖已固定于 `requirements*.txt`。`bash start.sh` 启动 8002 服务及原 AI 工作进程。初次克隆创建空库，需要注册账号；仓库不包含本机数据、密钥、运行环境或日志。

安装 `requirements-dev.txt` 后运行 `bash tools/verify_phase3.sh`，执行后端测试、属性/变异检查、静态检查、浏览器回归、迁移和性能验证。浏览器脚本使用 Playwright Chromium，首次使用可运行 `.venv/bin/python -m playwright install chromium`。测试创建临时数据库，模型服务由边界桩代替，不发起真实收费请求。

删除与恢复专项复现入口为 `bash tools/verify_task_trash.sh`，包含完整后端、9类故障变异与6类独立性质变异、关联资料保留和迁移恢复演练、浏览器流程及第一/二部分隔离检查。历史周按周末时的删除状态计算，后来恢复不会把整周已删除的任务重新计入历史占用。详见 `SPEC.md` 与 `EVIDENCE.md` 最新记录。

今日鼓励专项运行 `.venv/bin/python tools/browser_daily_encouragement.py`，验证300天轮换、午夜与日历边界、同日稳定、手机布局及读取失败时仍可使用预算与想法入口。

证据见 `EVIDENCE.md`，详细结果位于本机 `evidence/`。`tools/initialize_from_phase2.py` 仅用于首次本机导入，会拒绝覆盖任何非空第三部分数据库。验证脚本不会重复导入真实数据。
