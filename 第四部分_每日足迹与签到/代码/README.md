# 留白 · 第四部分：每日足迹与签到

双击上一级「打开留白.command」，打开 http://127.0.0.1:8003/ 。预算总览、任务、拆分、耗时、回收站和 DeepSeek 功能均保留。

## 每日足迹怎么用

- 总览「今日鼓励」右侧点击「今日签到」。通过「看看今天 / 休息一下」可以改成休息日，也可以撤销今日标记。
- 预算圆环下方、任务列表上方显示最近12周。点击日期查看当天实际投入及完成的任务、步骤；右上角可查看全年和历史年份。
- 绿色表示签到，浅暖色表示休息，格子中的小点表示真实耗时或完成进展。休息可以和当天进展同时存在；没有签到也会记录实际进展。
- 签到不自动完成任务、不虚增耗时、不改变预算。实际投入只读取原耗时账本，父任务和步骤的每条有效记录只计一次。
- 编辑、撤销耗时或完成记录后，足迹随事实更新；任务移入回收站仍保留历史足迹。撤销完成会移除那次有效完成，重新完成归入重新完成的日期；仅修改完成说明不会移动原日期。
- 日期统一按北京时间（Asia/Shanghai）。只能标记今天，过去可查看，未来不可点。跨日和回到页面时自动更新。
- 没有连续签到惩罚、排名或必须填满的要求。每一天都可以按自己的节奏来。

手机会将签到按钮放到鼓励文字下方。日历支持方向键移动、Enter打开，全年日历可在弹窗内左右滚动。

## 独立保存与已有账号

第四部分的完整代码在本目录，新功能集中于 `daily_footprints/` 和 `static/footprints.js/css`。`../规划书/` 保存本部分实施规范与验收说明。此前三部分的代码、数据和规划均保留。

本机第一次启用通过 SQLite 一致性快照复制第三部分的账号、任务、预算、步骤、完成记录和耗时；原账号密码可沿用，需要重新登录。已有本机 DeepSeek 配置按原字节复制到第四部分独立配置文件，没有重新调用模型验证或生成。签名密钥重新生成，Cookie 为 `taskflow4_session` / `taskflow4_csrf`，避免与前三版混用。

数据位于本版 `.local/tasks.sqlite3`，初始原始快照位于 `.local/phase3-import-backup.sqlite3`。之后第三部分与第四部分各自保存，不自动同步。复制时仍在排队或执行的旧 AI 请求会在新副本中标为中断，避免新入口重复执行。

新克隆不含本机数据库、密钥或虚拟环境；首次启动为空库，需要注册并自行配置 DeepSeek。请勿将 `.local/` 上传到 GitHub。

## 运行、初始化与验证

Python 3.14，固定依赖见 `requirements*.txt`。`bash start.sh` 启动本机 8003 服务和已有 AI 工作进程。首次运行会安装运行依赖。

已有第三部分数据时，**在第一次启动第四部分前**运行 `.venv/bin/python tools/initialize_from_phase3.py` 可导入独立副本。工具只读取第三部分，检查迁移前后业务记录一致、备份完整性和外键；第四部分已有非空数据库或导入备份时会拒绝覆盖。不要反复运行来同步数据。旧 `initialize_from_phase2.py` 在本版已停用。

安装开发依赖后运行 `bash tools/verify_phase4.sh`。浏览器验证需要 Playwright Chromium，可用 `.venv/bin/python -m playwright install chromium` 安装。检查包括完整后端回归、属性与故障变异、真实浏览器操作、迁移/回滚/恢复、目录隔离。验证仅使用临时测试库和模拟模型服务，不修改正式任务、不发起收费模型调用。

第四部分的 API 为 `/api/footprints/calendar`、`/api/footprints/day` 和 `/api/footprints/mark`。写入要求登录、CSRF、账号一致性、版本及幂等请求键；失败后可以核实并重试同一次标记。数据读取失败时预算和任务入口仍可使用。

详细契约见 `SPEC.md`，本次实际验证结果见 `EVIDENCE.md`，本机可重现日志与截图在 `evidence/`。继承的预算与执行规则可参阅 [第三部分说明](../../第三部分_负载建议与分析/代码/README.md)。
